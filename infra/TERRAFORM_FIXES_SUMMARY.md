## Issues Fixed

### 1. ✅ Removed Unwanted Root-Level Files
**Problem:** Documentation-only files in `infra/` root caused confusion.

**Files Removed:**
- `infra/provider.tf`
- `infra/variables.tf`
- `infra/versions.tf`
- `infra/outputs.tf`

**Why:** These files served no purpose as all Terraform operations run from environment directories (`infra/environments/dev` or `infra/environments/prod`).

---

### 2. ✅ Fixed Media Bucket Naming & Sharing Strategy
**Problem:** Dev and prod used different bucket names (`broandbro-menu-images-dev` vs `-prod`), contradicting the design of a single shared bucket.

**Fixed:**
- Updated both dev and prod to use: `broandbro-menu-images-shared`
- Dev creates the bucket (with `prevent_destroy = true`)
- Prod references it via `data.aws_s3_bucket` data source
- Updated all comments to clarify this is a SHARED bucket

**Files Changed:**
- `infra/environments/dev/variables.tf`
- `infra/environments/prod/variables.tf`
- `infra/environments/dev/main.tf` (comments)
- `infra/environments/prod/main.tf` (comments)
- `infra/bootstrap/bootstrap.tf` (comments)
- `.github/workflows/terraform-apply-dev.yml`

### 3. ✅ Updated terraform.tfvars.example Files

**Removed Deprecated Variables:**

- `ec2_public_key` - auto-generated by Terraform
- `db_password` - auto-generated by Terraform
- `rds_allocated_storage` - hardcoded in main.tf
- `rds_backup_retention_days` - hardcoded in main.tf
- `multi_az` - hardcoded in main.tf
- `cloudfront_price_class` - hardcoded in main.tf

**Added Comments:**
- Clarified that DB passwords and SSH keys are auto-generated
- Updated bucket name to shared bucket
- Simplified configuration to only user-modifiable values

**Files Changed:**
- `infra/environments/dev/terraform.tfvars.example`
- `infra/environments/prod/terraform.tfvars.example`

### 4. ✅ Fixed Security Group - Conditional RDS Public Access
**Problem:** RDS security group allowed `0.0.0.0/0` access on port 5432 regardless of environment.

**Fixed:**
- Used `dynamic` block to conditionally create public ingress rule
- Public PostgreSQL access ONLY in dev environment
- Prod environment: RDS only accessible from EC2 security group

**File Changed:**
- `infra/modules/security-group/main.tf`

**Security Impact:** Production RDS is now properly isolated.

---

### 5. ✅ Added existing_certificate_arn Variable & Wiring
**Problem:** GitHub Actions workflows referenced `existing_certificate_arn` but it wasn't defined or passed to the ACM module.

**Fixed:**
- Added `existing_certificate_arn` variable to both dev and prod environments (default: empty string)
- Wired it through to the ACM module in both environments
- Allows using pre-existing ACM certificates to avoid DNS validation delays

**Files Changed:**
- `infra/environments/dev/variables.tf`
- `infra/environments/prod/variables.tf`
- `infra/environments/dev/main.tf`
- `infra/environments/prod/main.tf`

### 6. ✅ Removed Unused Route53 Module Variables

**Fixed:**

- Removed `create_dev_records` variable (not used anywhere in the module)

### 7. ✅ Fixed ACM Module count/for_each Conflict
**Problem:** `aws_route53_record.validation` resource had both `count` and `for_each` meta-arguments, which are mutually exclusive.

**Fixed:**

- Kept only `for_each` which handles conditional logic via empty map `{}`
- Updated outputs to handle both new and existing certificate scenarios

**Files Changed:**
- `infra/modules/acm/main.tf`
- `infra/modules/acm/outputs.tf`

## Infrastructure Architecture Summary

### Environment Separation
```
infra/
├── bootstrap/          # One-time setup (S3 state bucket, DynamoDB lock, GitHub OIDC)
├── environments/
│   ├── dev/           # Development environment
│   └── prod/          # Production environment
└── modules/           # Reusable modules
```

### Shared Resources
- **Media S3 Bucket:** Created in dev, shared by all environments
- **Terraform State Bucket:** Created by bootstrap, shared by all environments
- **DynamoDB Lock Table:** Created by bootstrap, shared by all environments

### Environment-Specific Resources
Each environment has its own:
- Frontend S3 bucket + CloudFront distribution
- EC2 instance (backend) with auto-generated SSH key
- RDS PostgreSQL instance with auto-generated password
- Security groups (with environment-specific rules)
- CloudWatch logs, alarms, and dashboards
- Route53 DNS records
- ACM certificate (or reference to existing one)

---

## Security Improvements

1. **RDS Isolation:** Production RDS no longer allows public internet access
2. **SSH Keys:** Auto-generated and stored in AWS SSM (no manual key management)
3. **DB Passwords:** Auto-generated 32-character complex passwords stored in SSM
4. **Least Privilege:** Each EC2 instance has scoped IAM permissions

## Deployment Checklist

### First-Time Setup (One-time only)
1. **Bootstrap:**
   ```bash
   cd infra/bootstrap
   terraform init
   terraform apply
   ```
   
2. **Set GitHub Secrets:**
   - `AWS_ROLE_ARN`: Output from bootstrap (github_actions_role_arn)
   - Configure GitHub environments: `dev` and `prod`

### Deploy Dev Environment
```bash
cd infra/environments/dev
terraform init \
  -backend-config="bucket=broandbro-tfstate-us-east-1" \
  -backend-config="key=env/dev/terraform.tfstate" \
  -backend-config="region=us-east-1" \
  -backend-config="dynamodb_table=broandbro-tf-lock"
terraform plan
terraform apply
```

### Deploy Prod Environment
```bash
cd infra/environments/prod
terraform init \
  -backend-config="bucket=broandbro-tfstate-us-east-1" \
  -backend-config="key=env/prod/terraform.tfstate" \
  -backend-config="region=us-east-1" \
  -backend-config="dynamodb_table=broandbro-tf-lock"
terraform plan
terraform apply
```
