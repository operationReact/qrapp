CRITICAL ISSUE:
  PAID orders successfully created but NOT appearing in Kitchen Queue

ROOT CAUSE IDENTIFIED:
  OrderRepository query methods were missing the payment methods parameter
  - Repository queries had hardcoded string literals: IN ('PAY_AT_STALL', 'WALLET')
  - Query signatures lacked @Param("codPaymentMethods") parameter
  - OrderService.getLiveOrders() never passed COD_PAYMENT_METHODS to queries
  - Result: Enum comparison in JPA failed silently, breaking payment eligibility check

HOW IT WORKS AFTER FIX:
================================================================================

RAZORPAY (Online Payment):
  Order created: payment_status=PENDING, payment_method=RAZORPAY
    → Kitchen API query: ❌ NOT INCLUDED (PENDING + RAZORPAY not allowed)
    → Customer completes Razorpay payment
    → Webhook updates: payment_status → PAID
    → Kitchen API query: ✅ INCLUDED (PAID matches first condition)

PAY_AT_STALL (Cash on Delivery):
  Order created: payment_status=PENDING, payment_method=PAY_AT_STALL
    → Kitchen API query: ✅ INCLUDED (PENDING + PAY_AT_STALL in allowed list)
    → Kitchen staff preps immediately
    → Customer pays at stall

WALLET (Pre-funded):
  Order created: payment_status=PAID, payment_method=WALLET
    → Kitchen API query: ✅ INCLUDED (PAID matches first condition)
    → Kitchen staff preps immediately
